# 二、技术架构（已定稿，不要随意改）

```
浏览器（Vue3 + TS + Element Plus + Vite）
   │ HTTPS
   ▼
Nginx ──► Java 业务层（Spring Boot 3 · JDK 21 · 虚拟线程）
            │  职责：JWT 鉴权、RBAC、会话与消息落库、SSE 转发、限流、审计
            │  独占写入 MySQL 全部业务表
            │
            │ gRPC（TLS + HMAC 双向认证）
            ▼
        Python RAG 服务（Python 3.11 · grpc.aio）
            │  职责：Markdown 解析分块、Embedding、向量检索、Prompt 组装、LLM 调用、引用解析、边界拒答
            │
            ├──► Qdrant（向量库，payload 存引用所需全部字段）
            └──► 云端 LLM API（不部署本地大模型）
```

**四条铁律（违反即架构崩）**：

1. **浏览器只访问 Java**，不直连 Python、不直连 Qdrant、不直连 MySQL。
2. **Python 不写 Java 的业务表**（`sys_user`/`chat_*`/`doc_*` 等），它只通过 gRPC 返回结果。
3. **Python 不碰任何关系数据库**，它需要持久化的只有：原始文档（本地文件）、向量（Qdrant）、Skill（文件）、日志。
4. **MySQL 由 Java 独占**，一期同机部署，不规划外置。

**已定稿的技术决定**：

- JDK **21**（LTS），**启用虚拟线程**；SSE 链路走虚拟线程，CPU 密集任务用固定平台线程池。
- **禁止用 `synchronized` 保护 SSE 写**——JDK 21 上它会把虚拟线程 pin 在载体线程上（JEP 491 要到 JDK 24 才修）。SSE 写用「单线程队列」串行化。
- proto 是 Java/Python 唯一契约，**4 个 RPC**：`Chat`(server stream) / `IngestDocument`(client stream) / `DeleteDocument` / `HealthCheck`。
- 引用溯源数据全在 **Qdrant payload**，检索链路不需要回查 MySQL。

# 三、已确认的产品边界（不要越界）

**一期要做**：登录鉴权、文档上传（仅 `.md`/`.txt`）、解析分块、向量入库、自然语言问答（SSE 流式）、引用展示、多轮字段透传、领域边界拒答、违禁词过滤、会话历史、管理后台、审计日志、限流、TLS + HMAC。

**一期明确不做**（做了算越界，会被答辩问住）：

- WireGuard 组网、PDF/DOCX 在线解析、网页链接导入
- BM25 关键词检索、RRF 融合、Reranker 重排
- AI 答案人工审核、关键词库配置
- 多端接入（小程序/App）、系统监控告警面板
- 文档级 ACL 过滤（`permission` 字段只存不用）
- 本地大模型部署（Ollama/vLLM）

**对外表述禁令**：因为用了云端 LLM，**不得声称「数据完全本地化」「数据不出校」**。正确说法是「问题与检索片段会发送至第三方模型服务」。

# 七、硬性工作规则（这是前一位工程师踩过坑换来的，必须遵守）

## 1. 一切结论要有来源，三种标签只能选一种

- `【源：技术文档 §9.2】` —— 来自源文档的事实
- `【设计裁决：理由…】` —— 文档没规定、由设计者判断，**必须写理由**
- `【待确认 Q-xx】` —— 文档空白，**不许自己填**

**绝对禁止**：给一个看起来有依据、实际是自己编的来源。例如把「待确认的问题」当成「依据」引用，这是最严重的错误。

## 2. 禁止编造任何量化指标

不许出现 QPS、响应毫秒数、准确率、并发用户数——源文档一个都没给。所有性能参数只能写「建议值 + 待压测 + 待确认」。

## 3. 拿不准就问，不要自行假设

这是用户明确要求过的。宁可停下来问一句，也不要写一个"看起来合理"的答案。

## 4. 编号空间不要混用

| 前缀            | 含义         | 出处        |
| ------------- | ---------- | --------- |
| `UD-01~UD-08` | 用户决策       | 00 号 §1.5 |
| `D-01~D-04`   | **课程交付约束** | 00 号 §6.4 |
| `D-01~D-07`   | **交付物验收项** | PRD §7.4  |
| `Q-01~Q-22`   | 待确认问题      | 00 号 §8   |
| `C-01~C-17`   | 源文档冲突裁决    | 00 号 §7   |
| `T-01~T-22`   | 技术约束       | 00 号 §6.1 |

写 `D-` 时必须带来源前缀（如「PRD §7.4 D-02」），否则会被误读。

## 5. 改动要同步，不能只改一处

改计数（需求条数、用例条数、阶段数）时，至少要同步：PRD 统计、02 号覆盖段、03 号覆盖表、04 号 §8 覆盖表。**「全覆盖」这种声称最容易因为漏改一处而失真。**
