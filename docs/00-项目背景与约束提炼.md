1. 固化「哪些是文档能确认的事实」，避免下游文档在无依据处自由发挥。

### 1.3 溯源标注规则

| 标记 | 含义 |
|---|---|
| `【源：课题摘录 §X】` | 出自 S1 的某个小节（S1 简称「课题摘录」） |
| `【源：技术文档 §X.Y】` | 出自 S2 的某个小节（S2 简称「技术文档」） |
| `【源：技术文档 §X + §Y（推导）】` | 由 S2 多处条款合并推导，推导过程可复现 |
| `【待确认】` | 两篇文档均未规定，或需要用户/课程方确认 |
| `【待确认：文档未规定】` | 明确说明该空白属于文档缺失，非本文遗漏 |

**硬规则**：正文任何需求条目、约束条目、结论后面必须带来源标记；不允许出现无来源标记的条目；不允许编造量化数字（如并发数、准确率、响应毫秒数），凡是文档没有的指标一律标 `【待确认】`。

## 2. 项目定位（一句话）

面向华电学生的 **7×24 小时在线「校园百事通」**：把《学生手册》、教务管理规定、办事指南等制度文件构建为结构化知识库，学生用自然语言提问即可获得**带条款出处的精准答案**。
【源：课题摘录 §1】

## 4. 可确认的产品目标

| 编号 | 目标 | 来源 |
|---|---|---|
| G1 | 学生用自然语言提问即可直接拿到结论，**不必翻阅长篇手册**，且答案标注引用条款 | 【源：课题摘录 §1、§3】 |
| G2 | 建立可维护的结构化知识库：管理员上传文档即完成解析、分块、向量化入库，新增文档**无需全量重建** | 【源：课题摘录 §2 知识库构建模块；技术文档 §5.2】 |
| G3 | 通过**领域边界控制**把回答限定在校园制度范围内，无关问题（如「今天天气怎么样」）统一拒绝或引导，抑制幻觉 | 【源：课题摘录 §1、§5.2；技术文档 §8 第 4 步「问题分析」】 |
| G4 | 打通 `Vue → Java → gRPC → Python → SSE → Vue` 的完整可演示闭环，一期即可跑通「Markdown 入库 → 向量检索 → 流式问答 → 引用返回」 | 【源：技术文档 §14.1、§16】 |
| G5 | 保证服务间调用安全（TLS + HMAC + 安全组 IP 白名单）与业务侧最小 RBAC（JWT + BCrypt + 401/403） | 【源：技术文档 §4.4、§9.2、§12】 |

> 目标正交性说明：G1 是用户价值，G2 是内容运营能力，G3 是风险控制，G4 是可演示性，G5 是安全性，互不重叠。

### 6.3 安全约束

| 编号 | 约束 | 来源 |
|---|---|---|
| S-01 | 一期 `公网 gRPC + TLS + HMAC-SHA256 + 安全组 IP 白名单` 四项缺一不可；明文 gRPC 不合理 | 【源：技术文档 §9.2、§1.1】 |
| S-02 | Python 服务器只开放 gRPC 端口（如 50051），安全组仅允许 Java 服务器固定公网出口 IP | 【源：技术文档 §9.2、§10.2】 |
| S-03 | MySQL / Qdrant / Redis 等管理端口**不对公网开放** | 【源：技术文档 §9.2、§10.2】 |
| S-04 | gRPC 开 TLS，至少完成服务端认证；mTLS 放二期 | 【源：技术文档 §9.2】 |
| S-05 | HMAC 不能代替 TLS；HMAC 只用于 Java↔Python，Secret 不得下发前端 | 【源：技术文档 §1.2-5、§12.1】 |
| S-06 | HMAC 校验含：key-id 查密钥 → 时间戳误差窗口（如 ±60s）→ nonce 未使用 → 重算签名 → 恒定时间比较 | 【源：技术文档 §12.4】 |
| S-07 | 两台服务器必须配置 **NTP 时间同步**，否则时间戳校验会随机失败 | 【源：技术文档 §9.2、§12.6】 |
| S-08 | Secret 不得写入 Git，必须走环境变量或密钥管理 | 【源：技术文档 §12.6】 |
| S-09 | 日志不得打印 Secret、Signature 明文或完整敏感 Metadata | 【源：技术文档 §12.6】 |
| S-10 | 密码必须 BCrypt 哈希存储，禁止明文 | 【源：技术文档 §4.1、§4.4】 |
| S-11 | 必须显式配置 CORS，避免 Vue 预检被拦截 | 【源：技术文档 §4.4】 |
| S-12 | 必须统一返回 401 / 403 | 【源：技术文档 §4.4】 |
| S-13 | Spring Security 只解决接口级/角色级权限，**文档级 ACL 需在 Service 层实现**。`UD-07` 已定：**一期不做 ACL 过滤**，仅保留 `permission` 元数据字段占位，二期启用 | 【源：技术文档 §4.4】【UD-07】 |
| S-14 | HMAC 密钥支持 key-id 以便后期轮换；大文件上传可约定 SHA-256 摘要校验 | 【源：技术文档 §12.6】 |
| S-15 | 缓存 RAG 最终答案须谨慎：key 必须含用户、角色、文档版本，TTL 要短 | 【源：技术文档 §4.5】 |
